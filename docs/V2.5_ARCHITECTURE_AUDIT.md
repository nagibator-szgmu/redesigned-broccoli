# MEDSIM V2.5 ARCHITECTURE & HARDENING AUDIT

---

## 1. Current System State

MEDSIM представляет собой модульный симулятор клинического мышления (Clinical Reasoning Simulator) на стеке React 18 + Vite.
В версиях V2.0–V2.4 была построена каноническая цепочка:
$$\text{PATIENT} \to \text{ABCDE} \to \text{PROBLEM LIST} \to \text{DIAGNOSIS} \to \text{TREATMENT} \to \text{PHYSIOLOGICAL RESPONSE}$$
$$\to \text{REASSESSMENT \#1} \to \text{CLINICAL DECISION} \to \text{REVISED PLAN} \to \text{TREATMENT \#2} \to \dots \to \text{OUTCOME} \to \text{SCORE} \to \text{DEBRIEF}$$

### Аудит ключевых подсистем:

1. **Engine Layer (`src/engine/`):**
   * `patient.js`: Чистые функции инициализации (`initPS`), вычисления исхода (`computeOutcome`) и ограничения виталов (`clampPS`).
   * `deterioration.js`: Детерминированный тик декомпенсации (`tickDeterioration`), латентность эффектов и непрерывные инфузии (`applyContinuousEffects`).
   * `reassessmentEngine.js`: Чистый компаратор витальных параметров (`evaluateReassessment`), строгий $MAP$-гард ($MAP = \text{null}$ при отсутствии/невалидности АД), генератор снимков (`createReassessmentCheckpoint`).
   * `problemListEngine.js`: Автоматическое извлечение объективных синдромов (`deriveProblemList`) и динамическое отслеживание переходов (`evaluateProblemTransitions`: `ACTIVE`, `IMPROVING`, `RESOLVED`, `WORSENING`, `PERSISTENT`).
   * `decisionEngine.js`: Оценка клинической ситуации (`evaluateClinicalDecision`: `IMPROVED`, `UNCHANGED`, `WORSENED`) и формирование вариантов пересмотра плана (`CONTINUE`, `ESCALATE`, `MODIFY`, `NEW_TEST`, `STOP`, `EMERGENCY_RESPONSE`).
   * `safetyEngine.js`: Аналитическая классификация дефектов тактики (`evaluateClinicalSafety`: `critical_error`, `major_error`, `missed_opportunity`, `sequential_error`, `blind_polypharmacy`, `missed_escalation`).
   * `differentialEngine.js`: Детерминированное эвристическое сопоставление нозологий с доказательной базой (`✓ Подтверждено` vs `○ Требуется`) и явным дисклеймером.
   * `scoring.js`: Единственный источник истины для вычисления 0–100 баллов (`computeScore`).

2. **Data Layer (`src/data/`):**
   * 67 клинических случаев в `src/data/cases/` (SHA-256: `133299f4642412aa535b3a42075a478b65f2089ad5d782e6ba7a2b9695122fa9`).
   * 44 фармакотерапевтических вмешательства в `src/data/treatments.js`.
   * 29 диагностических методов в `src/data/diagnostics.js`.
   * 35 тем теории, конспектов и тестов.

3. **UI / Workstation Layer (`src/components/game/`, `src/screens/`):**
   * `DesktopWorkstation.jsx` (2-колоночная рабочая станция) и `MobileWorkstation.jsx` (1-колоночный мобильный интерфейс с доком).
   * `VitalsHUD.jsx`: Реанимационный монитор с цветовой индикацией и числовыми значениями.
   * `PatientRecordColumn.jsx`: Демография, анамнез, `TrajectoryPanel` и динамический `ProblemListPanel`.
   * `ReassessmentModal.jsx`: Диалог повторной оценки и формирования пересмотренного плана.
   * `DebriefPanel.jsx`: Полный разбор клинического цикла.

## 2. Technical, Clinical & UX Risks Identified

| Категория | Выявленный риск | Способ устранения в V2.5 |
| :--- | :--- | :--- |
| **Performance** | Размер основного JS бандла ~1.54 MB из-за синхронного импорта `three.js` (3D Emblem) в `MenuSidebar`. | Использовать `React.lazy()` + Suspense для `ThreeDTicker` и настроить Rollup `manualChunks` для Three.js. |
| **Clinical Safety** | Студент может вводить множество препаратов подряд (слепая полипрагмазия), не проводя повторную оценку. | Внедрить в `TreatPanel` и `useGameSession` визуальный индикатор-напоминание о необходимости проведения Reassessment при накоплении $\ge 3$ назначений. |
| **Decision Engine** | Недостаточно явная дифференциация экстренного жизнеспасающего ответа (`EMERGENCY_RESPONSE`) и деэскалации (`STOP / DE-ESCALATE`). | Расширить `decisionEngine.js` с явными состояниями `EMERGENCY_RESPONSE` (при критической декомпенсации) и `STOP / DE-ESCALATE` (при стабилизации). |
| **Safety Engine** | Отсутствие детекции `MISSED_ESCALATION` (когда при критических показателях $SBP < 75$, $SpO_2 < 85$, $GCS \le 8$ выполняются второстепенные рутинные действия). | Добавить в `safetyEngine.js` проверку `missed_escalation`. |
| **Debrief** | Дебрифинг должен полностью покрывать все 11 канонических пунктов клинического разбора. | Расширить `DebriefPanel.jsx` до 11-пунктовой структуры. |
| **Accessibility** | Некоторые витальные показатели и тренды полагаются на цветовой код. | Добавить явные текстовые метки и `aria-label` для скринридеров и режима повышенного контраста. |

## 3. Preservation Contract & Invariants

1. **67 клинических случаев:** Строго неизменны (контроль SHA-256).
2. **Базовый скоринг (`computeScore`):** Формула и веса неизменны.
3. **Физиологический движок (`deterioration.js`):** Единственный источник физиологической динамики.
4. **MAP Guard:** $MAP = \text{null}$ при отсутствии/невалидности АД.
5. **EventLog Integrity:** 0 дубликатов при перерендерах и переключениях.

## 4. Recommended Action Plan for V2.5

1. **Hardening Decision Engine (`src/engine/decisionEngine.js`):**
   * Добавить опции `EMERGENCY_RESPONSE` и `STOP / DE-ESCALATE`.
2. **Hardening Sequential Safety Engine (`src/engine/safetyEngine.js`):**
   * Добавить детекцию `MISSED_ESCALATION` и `BLIND_POLYPHARMACY`.
3. **Closed-Loop Nudge in Workstation UI:**
   * Добавить в `DesktopWorkstation` и `MobileWorkstation` ненавязчивое предупреждение о полипрагмазии без оценки.
4. **Enhanced 11-Point Debrief (`src/components/game/DebriefPanel.jsx`):**
   * Реализовать полную 11-пунктовую структуру дебрифинга.
5. **Performance & Bundle Code-Splitting:**
   * Оптимизировать загрузку `ThreeDTicker` через `React.lazy()` и настроить `vite.config.js`.
6. **Automated Testing & Verification:**
   * Создать `scripts/production-hardening-test.mjs` и запустить все 14 тестовых сьютов.
7. **Browser QA Verification:**
   * Проверить работу сценариев в браузере (Desktop и Mobile).
8. **Final Implementation Report:**
