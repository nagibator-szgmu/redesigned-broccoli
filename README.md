## О проекте

**MedSim** — интерактивный симулятор клинического мышления для ординаторов терапевтического профиля, студентов 4–6 курсов медицинских вузов, врачей-стажёров и начинающих специалистов.

Платформа решает ключевой разрыв медицинского образования: переход от теоретического знания стандартов к принятию быстрых решений в условиях дефицита времени и неполных данных до контакта с реальным пациентом.

### Ключевые особенности

- **4 симуляционных отделения** с индивидуальной клинической механикой:
  - **ОРИТ (ICU):** экстренная реанимация, жёсткий таймер, исходы: стабилизация либо летальный исход.
  - **Приёмное отделение (Admission):** экстренная сортировка, первичная стабилизация и выбор маршрута госпитализации.
  - **Поликлиника (Outpatient):** амбулаторный приём без обратного отсчёта, витальные показатели по требованию, раздельный сбор анамнеза заболевания и жизни, формулирование диагноза и маршрутизация.
  - **Многодневный стационар (Stationary):** суточный цикл курации (утренний статус -> диагностика -> терапия -> оценка динамики) до достижения критериев выписки.
- **Математический движок детериорации в реальном времени:**
  - Динамический пересчёт 7 параметров жизнедеятельности: ЧСС, систолическое и диастолическое АД, ЧДД, SpO2, Шкала комы Глазго (ШКГ), уровень боли (ВАШ).
  - Валидированный индекс тяжести (SOFA-like, шкала 0–20 баллов).
  - Шаг итерации детериорации 30 секунд (15 секунд в стресс-режиме).
  - Матрица отклика на 60 лекарственных препаратов и манипуляций с учётом латентного периода и терапевтического окна.
- **Интерактивный диалог с виртуальным пациентом (GigaChat LLM & Dialogue Tree):**
  - Свободный сбор анамнеза на естественном языке с поддержкой нейросети GigaChat и детерминированного дерева диалогов.
  - Продвинутый ролевой фильтр (anti-leak roleplay filter), предотвращающий раскрытие диагноза пациентом.
  - Клинический контроль витального статуса: автоматическое прекращение речевого контакта при угнетении сознания (ШКГ ≤ 8 баллов) и тяжелой гипоксии.
- **100% соответствие Клиническим рекомендациям Минздрава РФ:**
  - Каждый клинический сценарий верифицирован по актуальным протоколам и рубрикатору Минздрава России (cr.minzdrav.gov.ru).
  - Детерминированный алгоритмический дебрифинг: выявление фатальных врачебных ошибок, пропущенных обследований и необоснованной полипрагмазии.
- **Кроссплатформенность и нулевой порог входа:**
  - PWA-архитектура (Progressive Web Application): запуск в любом современном браузере без установки стороннего ПО.
  - Мгновенная загрузка интерфейса (<1.5 секунды) и стабильная работа даже при слабом интернет-соединении.
  - Адаптивность для ПК, ноутбуков, планшетов и смартфонов.
  - Строгая векторная дизайн-система: 100% SVG-иконки, 0 эмодзи в интерфейсе.

## Режимы симуляции

1. **Обычный режим (Case Select):** свободный выбор клинического случая по профилям и отделениям с фильтрацией.
2. **Случайный пациент (Random Case):** симуляция неотложного дежурства со случайной генерацией клинической ситуации.
3. **Стресс-режим (Stress Mode):** удвоенная скорость угасания витальных функций (шаг 15 сек), сокращённый лимит времени на принятие решений.
4. **Режим обучения (Curriculum Mode):** последовательный образовательный трек: «Теоретический конспект -> Решение клинических задач -> Контрольный тест». Темы открываются по мере подтверждения компетенций.
5. **Обучающий режим (Learning Mode):** контекстные подсказки на каждом этапе с пояснением патофизиологического механизма.
6. **Режим контроля и аккредитации (Assessment Mode):** скрытые витальные маркеры, отключение подсказок, строгий учёт времени и действий для объективной экзаменационной оценки.

## Регламент контроля достоверности документации (README Integrity Protocol)

> [!IMPORTANT]
> **ОБЯЗАТЕЛЬНЫЙ ПРОТОКОЛ ДЛЯ ИИ-АССИСТЕНТА И РАЗРАБОТЧИКОВ:**  
> После **каждого изменения** в проекте (добавление/редактирование клинических сценариев, тем теории, тестов, лекарственных препаратов, методов обследования, экранных модулей, компонентов диалога или служебных скриптов) **ИИ-ассистент обязан в автоматическом режиме проверять файл `README.md` на достоверность и немедленно актуализировать любые расхождения**.

### Чек-лист проверки достоверности после каждого изменения:

1. **Сверка количественных показателей клинической базы:**
   - **Кейсы:** выполнить `node scripts/validate-cases.mjs` и сверить общее число кейсов и их распределение по отделениям (`icu`, `admission`, `outpatient`, `stationary`).
   - **Темы теории:** сверить размер объекта `THEORY` в `src/data/theory.js` и дочерних тем в `src/data/topics.js` (должно быть 46 тем).
   - **Тестовые вопросы:** подсчитать общее число вопросов в `QUIZ_QUESTIONS` (`src/data/quiz.js`) (должно быть 163 вопроса).
   - **Препараты и методы обследования:** сверить количество записей в `src/data/treatments.js` (60) и `src/data/diagnostics.js` (37).
   - **Сертификаты:** сверить сумму пороговых и профильных наград в `src/data/certificates.js` (15 наград).
2. **Сверка архитектурного дерева файлов:**
   - При добавлении, перемещении или удалении файлов в `src/` актуализировать дерево каталогов в разделе «Архитектура системы».
3. **Контроль соответствия дизайн-системе:**
   - Выполнить `node scripts/check-no-emojis.mjs` — в кодовой базе не должно появляться символов эмодзи (строго векторные SVG).
4. **Проверка работоспособности сборки:**
   - Выполнить `npm run build` для подтверждения целостности модулей и отсутствия синтаксических ошибок.

## Запуск и разработка

### Предварительные требования

- **Node.js:** версия 18.0 или новее
- **npm:** версия 9.0 или новее

### Установка зависимостей

```bash
npm install
```

### Запуск локального сервера разработки

```bash
npm run dev
```

Приложение будет доступно по адресу `http://localhost:3000` (или порту, назначенному Vite).

### Сборка для продакшена и предпросмотр

```bash
npm run build
npm run preview
```

### Проверка качества кода и валидация данных

Перед каждым коммитом в репозиторий запускается комплекс проверок:

```bash
# Проверка соответствия линтеру ESLint
npm run lint

# Автоматическая валидация всех клинических кейсов (связи, тесты, препараты, методы)
node scripts/validate-cases.mjs

# Контроль чистоты интерфейса (строго векторные SVG-иконки, 0 эмодзи)
node scripts/check-no-emojis.mjs
```
