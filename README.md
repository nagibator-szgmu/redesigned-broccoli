# MED•SIM — Клинический тренажёр

Интерактивный медицинский симулятор для студентов-медиков и врачей. Игрок берёт роль врача приёмного отделения и должен стабилизировать критически больного пациента в условиях реального времени.

## Игровая механика

### Фазы игры

```
menu → order_tests → awaiting_results → diagnose → result
```

| Фаза | Что происходит |
|------|----------------|
| `menu` | Выбор кейса из списка |
| `order_tests` | Врач назначает обследования; пациент ухудшается в реальном времени |
| `awaiting_results` | Ожидание результатов (анимированный таймер); лечение можно назначать сразу |
| `diagnose` | Врач вводит диагноз текстом и подтверждает |
| `result` | Детальный разбор — оценка решений |

### Таймер и ухудшение

- Пациент ухудшается каждые **30 секунд** (интервал `detRef`).
- Каждый кейс имеет свой вектор ухудшения (`deterioration`) — дельта на каждый тик по каждому виталу.
- Если витал пересекает порог смерти (`deathThresholds`) — игра заканчивается летальным исходом.
- У каждого кейса есть лимит времени (`timeLimit`, в минутах).

### Структура кейса

```js
{
  id, name, age, gender,
  complaint,        // жалобы при поступлении
  vitals,           // начальные виталы: bp, hr, rr, temp, spo2
  initialGCS,       // начальный уровень сознания
  initialPain,      // начальный уровень боли (0–10)
  deterioration,    // дельта виталов каждые 30 сек
  deathThresholds,  // критические значения → летальный исход
  anamnesis,        // анамнез заболевания
  exam,             // данные физикального осмотра
  testResults,      // результаты обследований (объект id → текст)
  needDiag,         // обязательные обследования (для оценки)
  needTreat,        // обязательное лечение (для оценки)
  wrongTreat,       // противопоказанные препараты
  timeLimit,        // лимит времени в минутах
  tip,              // образовательная подсказка в разборе
  diagnosis,        // правильный диагноз (показывается в разборе)
}
```

## Система виталов

Отслеживаемые параметры пациента (`patientState`):

| Параметр | Обозначение | Норма |
|----------|-------------|-------|
| Пульс | `hr` | 60–100 уд/мин |
| Систолическое АД | `sbp` | 100–140 мм рт.ст. |
| Диастолическое АД | `dbp` | 60–90 мм рт.ст. |
| Частота дыхания | `rr` | 12–20 /мин |
| Сатурация | `spo2` | 95–100% |
| Температура | `temp` | 36,5–37,5°C |
| Уровень сознания | `gcs` | 15 (по шкале Глазго) |
| Боль | `pain` | 0–10 (ВАШ) |

Все виталы зажаты в физиологически достоверные диапазоны (`CLAMP_RANGES`).

## Диагностика и лечение

### Обследования (24 позиции)

Категории: кардиологические, лабораторные, лучевая диагностика, респираторные, неврологические.

### Препараты и вмешательства (25 позиций)

Каждое лечение имеет:
- **`eff`** — эффект на виталы при правильном назначении
- **`delay`** — задержка до появления эффекта (секунды, сокращены для геймплея)
- **`desc`** — краткое описание действия

**Противопоказания:** если препарат входит в `wrongTreat` кейса, применяются обратные эффекты (`ADVERSE_FX`) с клиническим обоснованием из `ADVERSE_REASONS`.

## Разбор после игры

После завершения показывается детальный дебрифинг:

1. **Динамика виталов** — начало → финал + дельта для каждого параметра
2. **Пропущенные обследования** — какие не назначили и почему они важны
3. **Опасные назначения** — какие препараты были противопоказаны и клиническое обоснование
4. **Хронология событий** — лог всех действий с временными метками
5. **Правильный диагноз** и образовательный совет

## Структура проекта

```
medsim/
├── src/
│   └── App.jsx        # весь код игры (~1400 строк)
├── index.html
├── vite.config.js
└── package.json
```

Весь игровой код находится в одном файле `src/App.jsx`. Архитектура использует React refs (`submitRef`, `psRef`, `cdRef` и др.) для доступа к актуальному состоянию внутри таймеров — это предотвращает баги с устаревшими замыканиями (stale closures).

## Как добавить новый кейс

1. Открой `src/App.jsx`, найди массив `CASES`.
2. Добавь объект, следуя структуре выше.
3. Укажи `testResults` — объект, где ключи совпадают с `id` из массива `DIAGNOSTICS`.
4. Укажи `needDiag` и `needTreat` — массивы `id` обязательных действий.
5. Укажи `wrongTreat` — массивы `id` опасных назначений (ключи должны быть в `ADVERSE_FX`).
6. Сохрани — кейс появится в меню автоматически.

## Деплой

### Cloudflare Pages (рекомендуется)

1. Залей репозиторий на GitHub
2. Cloudflare Dashboard → **Workers & Pages** → **Create** → вкладка **Pages** → **Connect to Git**
3. Выбери репозиторий
4. Настройки сборки:
   - **Build command:** `npm run build`
   - **Build output directory:** `dist`
5. Deploy

### Локальная сборка и предпросмотр

```bash
npm run build     # собрать в dist/
npm run preview   # предпросмотр на localhost:4173
```
