# План параллельной разработки MedSim: Распределение задач и Git-стратегия

> Документ подготовлен для синхронизации работы двух разработчиков над проектом MedSim.
> Текущий статус репозитория: `main` чистый, все предыдущие изменения закоммичены, рабочее дерево синхронизировано.

---

## 1. Как работать безопасно параллельно через GitHub (Zero Conflicts)

Главная опасность параллельной разработки — **конфликты при слиянии крупных монолитных файлов** (`ResultScreen.jsx`, `scoring.js`, `MedSimApp.jsx`).

Чтобы параллельная работа была на 100% безопасной:
1. **Сначала выполняется Фаза 0 (Пункт 0)** прямо в ветке `main`.
2. Только после коммита Фазы 0 разработчики создают свои ветки:
   - Разработчик 1: `git checkout -b feat/ui-redesign-results`
   - Разработчик 2: `git checkout -b feat/gastro-ai-patient-scoring`
3. **Строгое разделение зон по файлам**: ни один разработчик не редактирует файлы из зоны ответственности другого.
4. **Синхронизация через Pull Requests**: перед сдачей ветки подтягиваем актуальный `main` (`git fetch origin && git rebase origin/main` или `git merge origin/main`), проверяем `npm run build`.

## 2. Пункт 0 (Фаза 0): Стартовый каркас и контракты в `main` (Фундамент)

> **КРИТИЧЕСКИ ВАЖНО:** Делается ДО того, как разработчики создадут персональные ветки!
> Цель Фазы 0 — создать скелет папок, заглушек и утвердить контракты обмена данными, чтобы в процессе работы файлы не переименовывались и пути не ломались.

### Шаг 0.1. Файловый скелет (создаются папки и файлы-рыбы)
1. **Под новую специальность:**
   - Папка: `src/data/cases/gastroenterology/`
   - Файл: `src/data/cases/gastroenterology/index.js` (экспортирует пустой массив `export const gastroCases = [];`)
   - Подключение в `src/data/cases/index.js` (импорт `gastroCases` и добавление в общий список).
2. **Под вкладки экрана результатов:**
   - Папка: `src/components/result/tabs/`
   - Файлы-заглушки:
     - `ResultSummaryTab.jsx` (виталы, исход, итоговый балл)
     - `ResultErrorsTab.jsx` (структурированный список ошибок)
     - `ResultTheoryTab.jsx` (патофизиология, КР Минздрава, протоколы)
     - `ResultTimelineTab.jsx` (таймлайн действий / EventLog)
3. **Под ИИ-пациента:**
   - Папка: `src/components/game/chat/`
   - Файл-заглушка: `PatientDialogueWidget.jsx` (принимает пропсы и возвращает контейнер чата).

### Шаг 0.2. Фиксация контрактов данных (Data Contracts)

#### Контракт 1: Структура ошибки для разбора (`mistakes[]`)
Разработчик 2 формирует этот формат в `scoring.js`, а Разработчик 1 отображает его в `ResultErrorsTab.jsx`:
```javascript
// Объект ошибки в массиве result.mistakes:
{
  id: "err_wrong_anticoagulant",
  category: "treatment", // "treatment" | "diagnostic" | "anamnesis" | "tactical"
  severity: "critical",   // "critical" (-15 б.) | "warning" (-5 б.) | "info" (0 б.)
  title: "Необоснованное назначение гепарина",
  reason: "При признаках острого желудочно-кишечного кровотечения назначение антикоагулянтов противопоказано",
  penalty: 15,
  guidelineRef: "КР Минздрава РФ «Язвенная болезнь», разд. 3.2"
}
```

#### Контракт 2: Пропсы виджета ИИ-пациента (`PatientDialogueWidget.jsx`)
Разработчик 2 пишет логику внутри виджета, а Разработчик 1 встраивает виджет в сетку игрового экрана:
```javascript
<PatientDialogueWidget
  caseData={cd}
  patientState={ps}
  mode={settings.patientDialogueMode} // "hybrid" | "standard"
  onRevealAnamnesis={(key) => { /* регистрация собранного анамнеза для скоринга */ }}
/>
```

#### Контракт 3: Настройки симулятора
В глобальные настройки/стейт добавляется флаг:
```javascript
patientDialogueMode: "hybrid", // "hybrid" (чипсы + LLM ввод) или "standard" (только готовые вопросы)
```

## 3. Матрица разделения файлов и зон ответственности

| Зона ответственности | Разработчик 1 (Frontend & UI/UX) | Разработчик 2 (Core, Data & AI) |
| :--- | :--- | :--- |
| **Основной фокус** | Редизайн игрового экрана + Новый экран результатов (вкладки вместо свалки) + Декомпозиция UI | Новая специальность «Гастроэнтерология» + ИИ-пациент (гибрид) + Движок нормализации ошибок |
| **Разрешенные файлы для редактирования** | • `src/screens/game/*`<br>• `src/screens/ResultScreen.jsx`<br>• `src/components/result/tabs/*`<br>• `src/ui/*`<br>• Встраивание контейнера под чат в GameScreen | • `src/data/cases/gastroenterology/*`<br>• `src/data/cases/index.js`<br>• `src/engine/scoring.js`<br>• `src/engine/llmService.js`<br>• `src/components/game/chat/PatientDialogueWidget.jsx` |
| **Запрещенные файлы (не трогать)** | `src/engine/*`, `src/data/cases/*` | `src/screens/ResultScreen.jsx`, `src/ui/*` |

## 4. Задачи Разработчика 1 (Frontend / UI / Редизайн)

### Задача 1.1. Редизайн игрового экрана (`GameScreen`)
* **Цель:** Сделать интерфейс симуляции современным, клиническим, убрать тесноту, поддержать мобильные устройства и десктоп.
* **Объем работы:**
  - Обновить карточки действий (диагностика, терапия, осмотр, монитор витальных функций).
  - Сделать удобную компоновку (вкладки/сворачиваемые аккордеоны) вместо бесконечной простыни.
  - Разместить контейнер под `PatientDialogueWidget` (который наполняет Разработчик 2).
* **Файлы:**
  - `src/screens/game/EmergencyGameScreen.jsx`
  - `src/screens/game/OutpatientGameScreen.jsx`, `OutpatientPanels.jsx`
  - `src/screens/game/StationaryGameScreen.jsx`, `StationaryPanels.jsx`
  - Новые компоненты в `src/components/game/`

### Задача 1.2. Пересборка экрана результатов (`ResultScreen`) на 4 вкладки
* **Проблема:** Сейчас на экране навалено более 15 разрозненных блоков, есть дубли тестов и советов.
* **Решение:** Разложить экран по 4 вкладкам, используя компоненты из `src/components/result/tabs/`:
  1. **«Клинический итог» (`ResultSummaryTab.jsx`)**: балл (0-100), исход пациента, шкалы, дельта витальных функций, правильность диагноза.
  2. **«Разбор ошибок» (`ResultErrorsTab.jsx`)**: единый список ошибок из `result.mistakes` (категории: диагностика / терапия / анамнез / тактика) со ссылками на КР Минздрава.
  3. **«Обоснование и теория» (`ResultTheoryTab.jsx`)**: патофизиология, протоколы, ссылки на теоретические статьи.
  4. **«Хронология» (`ResultTimelineTab.jsx`)**: таймлайн действий врача (EventLog).

## 5. Задачи Разработчика 2 (Data / Engine / AI Backend)

### Задача 2.1. Специальность «Гастроэнтерология»
* **Цель:** Наполнить каталог `src/data/cases/gastroenterology/` клиническими кейсами по действующим КР Минздрава РФ:
  1. *Острый панкреатит* (отечная форма vs панкреонекроз, ранняя инфузия, шкала Бэлтазара).
  2. *Острое ЖКК* (язвенная болезнь желудка/ДПК, шкала Forrest, эндоскопический гемостаз, ИПП).
  3. *Язвенный колит* (активная фаза, тяжелая атака, терапия ГКС).
  4. *Цирроз печени* (декомпенсация, асцит, печеночная энцефалопатия, шкала Чайлд-Пью).
* **Файлы:**
  - `src/data/cases/gastroenterology/pancreatitis.js`
  - `src/data/cases/gastroenterology/bleeding.js`
  - `src/data/cases/gastroenterology/colitis.js`
  - `src/data/cases/gastroenterology/cirrhosis.js`
  - Регистрация в `src/data/cases/gastroenterology/index.js` и общем `src/data/cases/index.js`.

### Задача 2.2. Реализация ИИ-пациента (Гибридный режим)
* **Цель:** Оживить общение с пациентом без задержек.
* **Объем работы:**
  - В `PatientDialogueWidget.jsx` реализовать:
    - Блок быстрых кнопок-чипсов («Где болит?», «Как давно началось?», «Какие таблетки пили?», «Есть ли аллергии?»).
    - Текстовое поле ввода для произвольного вопроса врачом с отправкой в `src/engine/llmService.js`.
    - Учет тяжести состояния (если пациент в сопоре/коме или с сильной одышкой — он отвечает односложно или не может говорить).
  - Добавить переключатель «Стандартный / Гибридный с ИИ» в настройки.

### Задача 2.3. Движок разбора ошибок (`scoring.js`)
* **Цель:** Исключить дублирование данных и отдавать нормализованный массив `mistakes[]`.
* **Объем работы:**
  - Агрегировать штрафы за опасные назначения, пропущенные ключевые тесты и непроведенный сбор анамнеза в единый список по контракту из Пункта 0.
  - Добавить ссылки на пункты Клинических рекомендаций к каждой ошибке.

## 6. Пошаговый сценарий работы (Git Cheatsheet)

```
                       1. Выполнить Пункт 0 в main
                                   │
                       2. git push origin main
                                   │
        ┌──────────────────────────┴──────────────────────────┐
        ▼                                                     ▼
Разработчик 1                                         Разработчик 2
git pull origin main                                  git pull origin main
git checkout -b feat/ui-redesign-results              git checkout -b feat/gastro-ai-patient-scoring
        │                                                     │
(Работает в UI, screens, tabs)                        (Работает в cases, engine, chat)
        │                                                     │
git commit -m "feat(ui): ..."                         git commit -m "feat(cases): ..."
git push origin feat/ui-redesign-results              git push origin feat/gastro-ai-patient-scoring
        │                                                     │
        └──────────────────────────┬──────────────────────────┘
                                   │
                       3. Pull Requests в GitHub
                       4. Code Review & Merge в main
```

### Команды при возникновении изменений в main:
Если один разработчик уже влил свой PR:
```bash
git fetch origin
git merge origin/main
npm run build     # проверка сборки
git push origin <ваша-ветка>
```
