# МЕДСИМ — Структура проекта

Документ для передачи проекта другому разработчику. Здесь описано что делает каждый файл, как устроена архитектура и на что обратить внимание.

---

## Общая характеристика

**МедСим** — интерактивный медицинский симулятор (клинический тренажёр) для студентов-медиков и врачей.

Игрок берёт роль врача приёмного отделения и должен стабилизировать критически больного пациента в условиях реального времени: назначать обследования, ставить диагноз, назначать лечение — пока пациент ухудшается каждые 30 секунд.

**Формат:** обучение + развлечение. Каждый случай — реальная клиническая задача с таймером (5-12 мин), детериорацией пациента, критическими решениями и дебрифингом.

**Текущее состояние:** полностью рабочий SPA с 40 клиническими случаями, авторизацией, локализацией (RU/EN), темой dark/light и бэкендом на FastAPI. Деплой на Cloudflare Pages.

## Описание ключевых файлов фронтенда

### `src/main.jsx` — Точка входа

Подключает глобальные стили (`global.css`), рендерит `<App />` в `#root`.

### `src/App.jsx` — Роутинг

Определяет 4 маршрута:
- `/` — LoginPage (публичный)
- `/register` — RegisterPage (публичный)
- `/forgot-password` — ForgotPasswordPage (публичный)
- `/app` — MedSimApp (защищённый, требует авторизацию)

Оборачивает всё в `LocaleProvider` → `AuthProvider` → `BrowserRouter`. Если `VITE_DEV_MODE=true`, авторизация пропускается (для разработки).

**На что обратить внимание:** `ProtectedRoute` и `PublicRoute` — компоненты-обёртки, которые редиректят в зависимости от статуса авторизации.

### `src/MedSimApp.jsx` — Главный компонент (144 строки)

Ядро приложения. Управляет:
- **Фазами:** `menu`, `theory`, `leaderboard`, `certificates`, `result`, `order_tests`, `awaiting_results`, `diagnose`
- **Темой:** dark/light через `ThemeCtx.Provider`
- **Онбордингом:** если первый вход — показывает `OnboardingScreen`
- **ErrorBoundary:** ловит ошибки рендера, показывает экран с кнопкой перезагрузки
- **Dev-режимом:** красный баннер "РЕЖИМ РАЗРАБОТЧИКА"

**Как работает:** вызывает `useSettings()` и `useGameSession()`,然后 через `content` (IIFE) выбирает какой экран рисовать в зависимости от `game.phase`.

### `src/hooks/useGameSession.js` — Игровая логика (240 строк)

**Это самый важный файл в проекте.** Содержит ВСЮ игровую логику:

**Состояния (useState):**
- `phase` — текущая фаза игры
- `cd` — текущий случай (case data)
- `ps` — vital signs пациента (patient state)
- `prevPs` — предыдущее состояние (для отображения дельты)
- `selDiag` — выбранные обследования
- `orderedDiag` — назначенные обследования
- `revealedResults` — результаты тестов (пояляются по одному)
- `selTreat` — выбранные лечения
- `diagText` — текст диагноза (свободный ввод)
- `appliedFx` / `pendingFx` — какие эффекты применены/ожидают
- `timeLeft` / `totalTime` — таймер
- `eventLog` — лог событий (последние 30)
- `result` — итоговый результат

**Ключевые функции:**
- `startGame(caseId)` — инициализирует игру: выбирает случай, создаёт patient state, запускает таймер и детериорацию
- `handleSubmit(timeout, died)` — завершает игру: считает результат через `computeScore`, сохраняет в историю
- `handleOrderTests()` — назначает обследования, результаты приходят с задержкой 600-1000 мс
- `toggleTreatment(treatId)` — назначает лечение с задержкой эффекта (через `TREAT_FX[id].delay`)
- `applyTreatEffect(treatId)` — применяет эффект лечения к vital signs

**Таймеры:**
- Основной таймер: `setInterval` 1 секунда → при 00:00 автосдача
- Детериорация: `setInterval` 30 сек (15 в стресс-режиме)
- Эффекты лечения: `setTimeout` с задержкой из `TREAT_FX`
- Пауза при сворачивании вкладки (`visibilitychange`)

### `src/hooks/useSettings.js` — Настройки

Сохраняет в `localStorage`: `difficulty` (easy/normal/hard), `gameMode` (normal/stress/random), `theme` (dark/light), `language` (ru/en), `totalScore`, `casesPlayed`, `sessionHistory` (последние 50 игр).

### `src/engine/patient.js` — Пациент

- `CLAMP_RANGES` — физиологические границы виталов (hr: [15,230], sbp: [30,280], и т.д.)
- `initPS(cd)` — создаёт начальный patient state из данных кейса
- `computeOutcome(ps, cd)` — определяет исход: `dead`, `critical`, `unstable`, `stable`
- `clamp(v, lo, hi)` / `r1(v)` — утилиты

### `src/engine/scoring.js` — Подсчёт баллов

- `diagMatchRatio(diagnosis, diagText)` — доля совпавших слов диагноза (со стеммингом русских слов)
- `computeTimeBonus(elapsed, timeLimit)` — бонус 0-15 за скорость
- `computeScore(cd, selDiag, selTreat, diagText, finalPS, elapsedSec)` — итоговый балл 0-100

**Формула:**
```
Диагноз:      0-35 баллов (≥0.6 → 35, ≥0.3 → 20, >0 → 10)
needDiag:     0-20 баллов (пропорционально)
needTreat:    0-20 баллов (пропорционально)
wrongTreat:   -15 за каждое опасное лечение
Исход:        stable +20, unstable +10, critical +3, dead -20
Время:        0-15 бонус за скорость
```

**Оценки:** ≥85 Отлично | ≥70 Хорошо | ≥50 Удовлетворительно | <50 Неудовлетворительно

### `src/engine/deterioration.js` — Детериорация

- `tickDeterioration(ps, caseData, difficulty, gameMode)` — применяет дельту виталов с учётом сложности и режима
- `applyContinuousEffects(ps, activeTreatIds)` — применяет непрерывные эффекты (например, инфузия)
- `applyTreatmentEffects(ps, caseData, treatId)` — применяет разовый эффект лечения (+ проверка на wrongTreat)
- `resolveStatus(ps, caseData)` — определяет статус после изменения виталов
- `applyUnfinishedTreatments(ps, caseData, treatIds, appliedSet)` — применяет незавершённые лечения при подсчёте

### `src/ui/components.jsx` — UI-компоненты

Все визуальные компоненты в одном файле:
- **Btn** — универсальная кнопка (variants: primary, secondary, danger, ghost)
- **Vital** — отображение витала (значение + дельта + цвет по состоянию)
- **TimerCircle** — круговой таймер с SVG
- **GCSBadge** — бейдж шкалы Глазго
- **PainBadge** — бейдж уровня боли (ВАШ 0-10)
- **CheckRow** — строка с чекбоксом (для списка обследований/лечений)
- **ResultCard** — карточка результата

### `src/ui/theme.js` — Темы

Экспортирует объекты `DARK` и `LIGHT` с цветами для каждого элемента UI. Формат: `HEX-коды`. Также `CODE` (цвета для кода) и `SER` (цвета для результатов) и `FONT` (шрифты).

### `src/locale/` — Локализация

- `t(key, params)` — берёт строку из текущей локали, подставляет `{param}`
- `useTranslate()` — хук, возвращает `t` привязанный к текущей локали
- `LocaleContext` — React Context с `locale` и `setLocale`
- `ru.js` / `en.js` — объекты перевода (плоские, ключи вида `"game.order_tests"`)

## Описание ключевых файлов бэкенда

### `app/main.py` — Точка входа

Создаёт FastAPI app, добавляет CORS middleware (из `settings.cors_origins`), монтирует роутеры v1, при старте вызывает `init_db()`.

**Эндпоинты:**
- `GET /` — `{"status": "ok", "service": "MedSim Backend"}`

### `app/core/config.py` — Конфигурация

`Settings` — frozen dataclass, загружает переменные из `.env` через `python-dotenv`:
- `DATABASE_URL` — строка подключения к PostgreSQL
- `JWT_SECRET` — секрет для HS256
- `JWT_EXPIRE_MINUTES` — время жизни токена (60 мин)
- `CORS_ORIGINS` — список разрешённых origins
- `APP_ENV`, `HOST`, `PORT`

### `app/db/session.py` — База данных

- `engine` — SQLAlchemy engine (lazy init, pool_size=5, max_overflow=10, pool_pre_ping=True)
- `SessionLocal` — фабрика сессий
- `get_db()` — FastAPI dependency (generator, yield + close)
- `init_db()` — `Base.metadata.create_all()`

### `app/models/user.py` — Модель User

Таблица `users`:
| Поле | Тип | Ограничения |
|---|---|---|
| `id` | String(36) | PK, UUID4 |
| `email` | String(255) | UNIQUE, indexed |
| `username` | String(100) | UNIQUE, indexed |
| `password_hash` | String(255) | NOT NULL |
| `created_at` | DateTime | default=utcnow |

### `app/schemas/auth.py` — Pydantic-схемы

- `RegisterRequest` — email (EmailStr), username (3-100 chars), password (6-128 chars)
- `LoginRequest` — email, password
- `UserResponse` — id, email, username, created_at
- `TokenResponse` — access_token, token_type="bearer", user: UserResponse

### `app/repositories/user_repo.py` — Репозиторий

Функции (принимают `Session`):
- `get_by_email(db, email)` — поиск по email
- `get_by_username(db, username)` — поиск по username
- `get_by_id(db, user_id)` — поиск по ID
- `create(db, email, username, password)` — создаёт пользователя, коммитит
- `exists(db, email=None, username=None)` — проверка существования

### `app/services/auth_service.py` — Сервис авторизации

- `hash_password(password)` — bcrypt хеш
- `verify_password(plain, hashed)` — проверка bcrypt
- `create_access_token(data)` — JWT HS256 с expiry
- `decode_access_token(token)` — декодирование/валидация
- `register(db, data)` — полный flow: проверка уникальности → хеш → создание → токен
- `login(db, data)` — проверка credentials → токен
- `get_current_user(db, token)` — декодирование токена → поиск пользователя

### `app/api/v1/auth/router.py` — Эндпоинты авторизации

| Метод | Путь | Описание | Авторизация |
|---|---|---|---|
| POST | `/api/v1/auth/register` | Регистрация | Нет |
| POST | `/api/v1/auth/login` | Логин | Нет |
| GET | `/api/v1/auth/me` | Текущий пользователь | Да (Bearer) |

### `app/dependencies/auth.py` — DI для авторизации

`get_current_user()` — FastAPI dependency. Извлекает Bearer-токен из заголовка `Authorization`, декодирует, возвращает пользователя.

## Игровой цикл

```
┌─────────────┐
│  MenuScreen  │  Выбор случая + фильтры + настройки
└──────┬──────┘
       │ startGame(caseId)
       ▼
┌─────────────┐
│ order_tests  │  Назначение обследований. Пациент ухудшается каждые 30 сек.
└──────┬──────┘
       │ handleOrderTests()
       ▼
┌───────────────────┐
│ awaiting_results  │  Результаты приходят по одному (600-1000 мс). Можно назначать лечение.
└──────┬────────────┘
       │ toggleTreatment() + setDiagText()
       ▼
┌──────────┐
│ diagnose  │  Ввод диагноза текстом + выбор лечения
└──────┬───┘
       │ handleSubmit()
       ▼
┌──────────────┐
│ ResultScreen │  Баллы, оценка, динамика виталов, дебрифинг
└──────────────┘
```

**Детериорация:** каждые 30 сек (15 в стрессе) виталы меняются на дельту из `caseData.deterioration`. Множители: difficulty × gameMode.

**Статусы пациента:**
- `stable` — всё ОК
- `deteriorating` — ухудшается
- `critical` — критическое состояние (sbp < 80 или spo2 < 80 или gcs < 8)
- `dead` — смерть (пороги из `deathThresholds`)

**Режимы:**
- **Обычный** — стандартная сложность
- **Стресс** — ×2 скорость детериорации, ×0.5 время
- **Случайный** — случайный случай без выбора

**Сложность:**
| Уровень | Множитель времени | Множитель ухудшения |
|---|---|---|
| Лёгкая | ×1.5 | ×0.65 |
| Средняя | ×1 | ×1 |
| Сложная | ×0.7 | ×1.5 |

### Структура случая (cases.js)

```js
{
  id,                          // номер
  name,                        // "Фамипостроиливич Иванов Иван Иваныч"

  complaint,                   // жалобы при поступлении
  vitals: { bp:"120/80", hr:90, rr:18, temp:37.0, spo2:96 },

  deathThresholds: { sbp:48, spo2:65, gcs:4, hr:195 },      // пороги смерти
  anamnesis,                   // анамнез
  exam,                        // физикальный осмотр
  severity,                    // critical / moderate
  category,                    // cardiac / neuro / ...
  diagnosis,                   // правильный диагноз (текст)
  testResults: { ecg:"...", troponin:"🔴 ..." },  // результаты тестов

  needTreat: ["aspirin", "heparin"],   // обязательное лечение

  timeLimit: 12,                       // начальное время (минуты)
  tip,                          // совет
  debrief: { explain:"..." },   // клинический разбор
}
```

### 35 диагностических тестов

Категории: кардио, лаборатория, дыхание, визуализация, нейро. Каждый тест имеет `MISSED_TEST_REASONS` — почему его важен.

### 40 лечений

Каждое лечение имеет:
- `eff` — эффект на виталы при правильном назначении
- `delay` — задержка до эффекта (в игровых секундах)
- `desc` — описание действия
- `continuous` — флаг непрерывного эффекта (инфузия)
- `ADVERSE_FX` — обратные эффекты при противопоказании
- `ADVERSE_REASONS` — клиническое обоснование

## Архитектурные особенности

### Фронтенд

- **Нет UI-библиотек** — весь CSS через инлайн-стили в JS-объектах
- **Нет state manager** — состояние через useState + useContext
- **Все данные на фронте** — 40 случаев, 40 лечений и т.д. зашиты в `data/*.js`
- **Файлы < 200 строк** — правило из CLAUDE.md, все файлы компактные
- **JSDoc** — комментарии для функций
- **Early returns** — избегать вложенности if/else
- **Native JS в приоритете** — минимум зависимостей

### Бэкенд

- **Чистая слоёная архитектура:** Router → DI → Service → Repository → Model
- **Versioned API:** `/api/v1/...` — готов к расширению
- **Repository pattern** — чистое разделение запросов и бизнес-логики
- **Frozen settings** — иммутабельный dataclass конфигурации
- **Lazy DB init** — engine создаётся при первом запросе, не при импорте
